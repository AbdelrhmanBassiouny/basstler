# workflow-cutover — standing rules

- The base-change credential is unverified in the Action. A session's own git-proxy credential refuses a base change while its MCP client performs one; the Action's credential is a third identity again. Verify it with a real base change before relying on it.
- Two operations stay outside the harness. Tag pushes and branch deletes get a 403 through a session's git proxy and no tool substitutes, so `tooling-branch-retirement`'s last two steps are the user's to run. A session can do every verification and prepare the exact commands.
- Site code names nothing twice (owner, #6). Locations, branches, repository URLs, REST fields and pull request states come from `ProjectLocation`, `PersonalNotesSetting`, `Repository`, `PullRequestField` and `PullRequestState`; git runs through `GitCommandRunner`, pages render through `TemplatePage`, and tests read values from the dataset or those enums.
- Callers basstler ships are event-only. The Actions budget allows no `schedule` and has no exception for one, so a duty that would want a timer runs on the next pull request event or a `workflow_dispatch`. Every example caller is an `ExampleCaller` member in the tests, and calls `@main` with the same `basstler_branch_or_tag`; the tag-only release rewrites no file.
- A push made with the Action's `GITHUB_TOKEN` starts no workflow. A restack the Action pushes gets no CI on the restacked pull request, and nothing may assume that it does.
- plan-site-action goes before any further Artifact-only dashboard work: a feature that only improves the Artifact page waits for the site, or lands as shared rendering.
